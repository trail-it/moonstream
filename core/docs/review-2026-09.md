# 独立审查记录（2026-09）

一轮**对抗性代码审查**的结果与处置。审查由一个独立代理执行：只读代码、只运行
`moon -C core run --target native cmd/replay` 观察行为，**不修改任何文件**。
本文记录它报告的每一条、我们的判定与处置，包括判定为"不是缺陷"的条目。

## 结论

审查确认了 8 条真实问题（2 条高危），全部已修复并补了回归测试；另有 3 条判定为
"文档不准确"或"设计取舍"，只改文档不改行为。

## 判定为"文档问题"，只改文档

| 条目 | 判定 |
|---|---|
| 三个不透明类型的 docstring 声称"内部状态不会出现在 `.mbti`" | 不准确：`.mbti` 会显示一个不透明字段名。改成"改内部字段不影响公开接口，改类型名会" |
| `semantics.md` 说"数字正在扫描表现为 `Pending`" | 对数组元素不成立（数组没有 `KeyComplete`）。已限定 `Pending` 只用于对象成员，并写明数组元素在完成前是 `Missing` |
| `adapters/llm-mb` 目录名笔误 | 已修正为 `adapters/llm_mb`，并补上 `adapters/mizchi_llm` |

## 判定为设计取舍，不修改

| 条目 | 判定 |
|---|---|
| 数组元素在值完成前是 `Missing` 而不是 `Pending` | 保持现状。要让数组元素也进入"未完成"状态需要新增值开始事件，会改变公开事件契约；文档已如实说明差异 |
| `{"a":123abc}` 报 `InvalidSyntax` 而不是 `InvalidNumber` | 保持现状。`123` 本身是合法数字，`abc` 是容器层面的语法错误；这与"数字内部字符"的判定规则一致 |

## 流程改进

- 测试辅助函数 `render_event` 现在把 `Span` 纳入渲染。此前它丢掉区间，导致"分块不变性"
  永远无法发现区间口径的偏差——**不变量测试必须覆盖被声明为不变量的每个字段**。
- 新增的每一条回归测试都写明"修复前的错误行为"，避免以后被当成快照随手更新掉。
